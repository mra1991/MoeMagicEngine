## Content ownership and longer-term outcome

Root `assets/` is a source-library/provenance and technical-fixture corpus, never an implicit
fallback for a game. The approved v1.1.0 workflow turns the reviewed selection into a discoverable
source: **reuse project assets → search shared library → Add to Project → only then consider
external content**. The installed library is read-only source storage. Copies carry dependencies
and provenance, remain editable and build without the library. Neither Player gains a mount.
Do not delete assets just because they are currently unreferenced. See the
audio inventory (see installed documentation/source reference) and model policy (see installed documentation/source reference).
Build Game uses the selected project's saved declaration and current dependency closure, not
historical sample file totals or all root-library content.

Grow both games into complete, independently buildable multi-scene examples. Ultimate Platformer's
introductory, chase and kart levels are the first milestone; continue naturally improving the game
through the extended 1.x capability releases. This document alone does not authorize implementation
or require unrelated Pot Pursuit expansion. The owner approved
retiring the root technical showcases and chair in
v0.12.7 (see installed documentation/source reference). This supersedes the
earlier retention direction. Root retirement is implemented; useful tests use test-owned
fixtures. Neither game must gain new content to authorize this retirement, and both current
projects, Basic3D and downloaded libraries remain protected.

This is practical groundwork for v2 AI-assisted development (see installed documentation/source reference):
an LLM should increasingly use explicit project context and ordinary authoring/command/query
capabilities, rather than editing engine internals for routine game tasks. It does not authorize
an LLM integration, new API surface, or a new engine milestone.
